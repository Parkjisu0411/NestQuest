# 자료 재사용 정책

2026-09-21 적용.

| 자료 | 저장 및 갱신 |
| --- | --- |
| 서울 단지 목록 | 기존 카탈로그를 재사용. 데이터 관리에서 명시적으로 새 목록 조회 |
| 확인된 단지 상세·좌표 | 카탈로그에 영구 저장. 상세정보 갱신 옵션으로 다시 확인 |
| 주소 검색 | 주소별 정상 좌표 또는 결과 없음 응답을 30일 저장. 오류·복수 결과는 저장하지 않음 |
| 통근 | 기존 출발 좌표·출근역 기준 30일 정책 유지 |
| 실거래 당월 및 직전 2개월 | 자치구·거래 월별 완료 자료를 1일 저장 |
| 실거래 그 이전 월 | 자치구·거래 월별 완료 자료를 30일 저장 |

실거래는 최근 12개월만 가격 산출에 사용한다. 거래 취소·정정 반영을 위해 과거 월에도 만료 시간을 둔다. 조회가 중단되면 완료된 월 캐시는 유지하고 실패하거나 미완료인 월은 저장하지 않는다. 거래 0건인 정상 응답도 재사용한다. 데이터 관리의 ‘저장된 실거래도 새로 조회’는 캐시를 무시하고 갱신한다.

주소 검색과 월별 실거래 캐시는 IndexedDB v3의 별도 providerCache 저장소에 둔다. API 키·헤더·요청 URL을 저장하지 않으며, 캐시는 사용자 백업 대상에 넣지 않는다. 기존 카탈로그와 임장 기록·사진·초안 저장소는 유지한다. 캐시 저장 실패 시 API 결과는 그대로 사용하고 이후 재조회할 수 있다.

최초 조회와 만료된 월의 갱신에는 여전히 API 시간이 필요하다. 화면 이동 시 자동 조회 취소 정책은 이 변경과 별개다. 이 정책은 호출을 줄이지만, 아직 매칭되지 않은 단지의 가격·면적을 생성하지는 않는다.

## 새로고침 후 작업 재개

단지의 `syncChecks`에 처리 완료 시각과 입력 식별값을 저장한다. 별도 메모리 Set을 완료 기준으로 사용하지 않는다.

- 기본정보·유형·좌표가 확인된 단지는 건너뛴다. 일반 아파트가 아닌 것으로 확인된 단지도 후속 통근·가격 보강에서 제외한다.
- 정상 조회 후 좌표를 찾지 못한 결과와 경로 없음 결과는 1일 동안 재시도하지 않는다. 인증·한도·통신·저장 오류를 완료로 기록하지 않는다.
- 실거래 매칭은 구별로 한 번 수행하고, 거래 0건 및 미연결 결과에도 완료 상태를 저장한다. 1일이 지나거나 조회 월·구의 단지 구성·단지명·주소·유형이 달라지면 재매칭한다. 월별 원본 캐시 정책은 그대로다.
- 출근역·출발 좌표 변경은 해당 통근 결과만 무효화한다.
- 진행 문구는 실제 미완료 작업에만 표시한다. 갱신할 항목이 없으면 조회 상태 UI도 표시하지 않는다.
- 기존 저장 자료에는 완료 메타데이터가 없으므로 적용 직후 최초 한 번은 구별 가격 매칭 등이 필요하다. 성공적으로 저장된 이후에는 새로고침으로 전체 처리하지 않는다.

## APK 초기 자료와 제한된 자동 갱신

PC 데이터 관리의 ‘APK 초기 자료’에서 기존 카탈로그를 내보낸다. 필요할 때만 ‘전체 자료 준비’를 실행하며 선택한 지역 전체를 순차 수집한다. 화면을 유지해야 하고 서비스 한도·중단 시 완료된 자료를 보존한다. 이 작업은 자동 실행하지 않는다.

내보내기는 단지·평형·거래·공식 역 기준 카카오 통근·수집일·완료 메타데이터만 포함한다. 관심/후보/임장/평가/사진/조사 메모/키는 포함하지 않는다. 개인 설치용 파일이며 Git에서 제외한다. 타인에게 데이터가 포함된 APK를 배포하기 전에는 공급자별 저장·재배포 조건을 별도 확인한다.

1. 기존 자료가 있는 PC의 같은 브라우저 주소에서 설정 → 데이터 관리 → APK 초기 자료 → APK 초기 자료 내보내기.
2. `npm run seed:prepare -- "다운로드한 nestquest-bootstrap.json의 경로"` 실행.
3. `npm run android:apk` 실행. 위치/가격/통근 포함 건수를 빌드 로그에서 확인.

검증된 자료는 local-data/bootstrap.json에 보관하고 public/bootstrap.json으로 복사해 APK와 웹 오프라인 셸에 포함한다. 실제 수집일을 빌드 시각으로 바꾸지 않는다. 자료가 없으면 빌드에서 ‘초기 자료 없음’을 안내하며 첫 실행은 기존 API 경로를 사용한다. 형식이 잘못된 자료는 빌드를 중단한다.

앱은 사용자 저장소 읽기에 성공한 뒤 초기 자료를 병합한다. 동일 버전은 다시 적용하지 않고, 최신 기기 기본정보·가격·통근과 사용자 기록을 보존한다. 초기 자료를 읽지 못해도 사용자 저장소와 앱 사용은 유지된다. 사용자 저장소 읽기 실패 시에는 기존 복구 화면을 유지한다.

자동 보강은 선택 단지 → 최종 후보 → 관심 → 방문 → 현재 목록 페이지 순서로 최대 50개, 실거래는 우선 3개 구까지다. 위치 미확인 단지도 목록 페이지 범위에 포함된다. 최초 자료가 전혀 없으면 20개로 시작하며 전체 준비는 별도다. 지도 화면 범위 자체로 자동 조회 대상을 선정하는 기능은 아직 사용하지 않는다.

통근의 30일 유효 기간은 갱신 판단에만 사용한다. 동일 출발/도착 좌표의 오래된 결과도 원래 조회일과 함께 표시하고 실패 시 유지한다. 목적지가 바뀐 결과는 표시하지 않는다. 가격도 저장된 값과 기준일을 먼저 표시한다. 목록 순서는 API 갱신 중 유지하며 사용자가 다시 정렬할 수 있다.
