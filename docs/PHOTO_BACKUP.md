# 사진 포함 백업 형식과 검증

## 원본 정리 보완 · 2026-09-18

완료 임장 수정에서 제거한 원본은 다른 방문에서 참조하지 않을 때 기록 저장과 같은 트랜잭션으로 삭제한다. 설정에서 미사용 원본을 먼저 점검하고 별도 삭제 버튼으로 정리할 수 있다. 정리 실행 시 실제 저장된 기록을 다시 확인하며 기록이 없거나 손상되어 참조를 판단할 수 없으면 삭제하지 않는다. 초안의 원본은 별도 저장소에 있어 이 정리 대상이 아니다. 관련 삭제/중단/공유 원본 보호는 트랜잭션 대역 테스트로 검증했으며 실제 사용자 원본을 일괄 삭제하는 검증은 하지 않았다. 백업 크기 제한은 여전히 200MiB이며 압축하지 않는다.

구현일: 2026-09-18

설정에서 사진 포함 백업 만들기는 `.nestquest` 파일을 다운로드한다. 기록만 JSON 백업도 현재 v2이며 기존 v1 복원을 지원한다. 복원 파일 선택은 두 형식을 모두 지원한다.

## 파일 구조

1. UTF-8 서명 `NESTQUEST1` + LF (11바이트)
2. JSON manifest 바이트 길이 (4바이트 unsigned big-endian)
3. UTF-8 JSON `{ backup, photos }`
4. manifest 순서의 사진 원본 바이너리 (변환·압축하지 않음)

`backup`은 nestquest-backup v2 문서이며 단지 자료를 포함한다. 기존 v1도 복원할 수 있다. 각 photos 엔트리는 blobKey, MIME type, 바이트 크기, SHA-256을 포함한다. 관찰 항목의 photoIds는 기존 기록 안에 보존된다. 파일 크기 최대 200MiB, manifest 최대 32MiB. 암호화 형식은 아니다. 읽는 동안 원본은 Blob slice로 분리하고 사진별로 해시를 확인한다.

원본이 없는 사진이나 읽기 오류가 있으면 전체 백업을 중단한다. 부분 성공을 전체 백업으로 표시하지 않는다. 이때 기록 전용 JSON 백업을 사용할 수 있다. 작성 중인 임장 초안과 기록에서 제거된 잔여 사진 Blob은 백업 대상이 아니다.

## 복원

파일 선택 시 버전·기록 스키마·사진 목록·중복/알 수 없는 키·크기·해시·파일 끝을 검증하고 방문 수/원본 수를 표시한다. 복원 버튼을 누르면 다시 검증 후 사용자 상태·원본 사진·초안 저장소를 하나의 readwrite 트랜잭션으로 교체한다. 새 원본 삽입이나 기존 데이터 정리 중 오류가 발생하면 트랜잭션을 중단한다. 완료 이벤트 이후에만 화면 상태를 교체한다.

현재 기록과 사진은 덮어써지고 초안은 지워진다. JSON 백업을 복원하면 원본 없이 메타데이터만 복원된다. 확인 화면에 차이를 표시한다.

새 기기에서는 초기 설정 첫 화면의 `백업으로 시작` → `/restore`에서 바로 파일을 선택할 수 있다. 초기 설정을 끝낼 필요가 없다. 검증한 파일의 이름과 방문/사진 수를 확인한 뒤 별도 복원 버튼으로 실행한다. 검증·저장 중 중복 실행을 막고 오류가 나면 재시도할 수 있다.

## 검증 결과

- 자동 테스트 190개·빌드·lint 통과.
- 원본 바이트/MIME/관찰 연결 왕복, JSON 호환, 원본 누락, 사진 변경·잘림·추가 바이트, 잘못된 키/크기/중복/버전 거부 테스트.
- 트랜잭션 대역으로 상태·사진·초안의 동일 트랜잭션 사용, 완료 대기, 동기 오류의 전체 중단 검증.
- 인앱 브라우저에서 실제 사진 포함 백업 파일 생성·다운로드 확인. 다운로드된 파일 6,049바이트를 실제 파서로 읽어 방문 2개·SVG 원본 2개 검증.
- 실제 파일을 브라우저 복원 선택기에 넣어 검증 및 `방문 2개 · 사진 원본 2개 포함` 표시 확인 후 취소. 기존 데이터의 최종 교체는 실행하지 않았다.

### 독립 저장소 전체 복원 검증 (2026-09-18)

- 기존 개발 주소(5173)와 다른 origin `http://127.0.0.1:5174`의 빈 IndexedDB로 시작했다. 같은 인앱 브라우저이며 실제 별도 기기 시험은 아니다.
- 초기 설정 → 백업으로 시작 → 실제 다운로드 파일 선택 → 방문 2개/원본 2개 미리보기 → 복원 → 탐색 화면 이동을 확인했다.
- 390×844 화면에서 복원 확인 화면을 점검했다. 초기 설정 없이 탐색 조건, 방문 시각, 메모를 복원했다.
- 사진이 있는 방문으로 직접 진입하고 새로고침한 후 두 SVG 원본이 모두 320×200으로 디코딩됐다. 공통 사진 B와 `역·정류장까지 이동` 연결 사진 A가 유지되고 항목의 사진 보기 링크가 해당 사진으로 이동했다.
- 복원 후 사진 포함 백업을 다시 다운로드했다. 실제 파서로 원본과 재백업을 읽고 전체 앱 상태의 deep equality, 두 사진의 blobKey/MIME/크기/SHA-256 일치를 확인했다. 방문 중복이나 원본 바이트 변경 없음.
- 기존 5173 저장소의 최종 교체는 실행하지 않았다. 자동 테스트 190개, 빌드, lint 통과.

남은 검증: 실제 모바일 다운로드/파일 선택·카메라 원본(JPEG/HEIC 등), 200MB 근처 파일의 메모리·저장 용량 실패. 단위 테스트의 트랜잭션 대역은 실제 저장 용량 초과 시험을 대체하지 않는다.

## 2026-09-21 추가 검증

빈 QA 저장소에 합성 사진 백업을 최종 복원해 임장 항목과 사진 원본 연결·화면 표시를 확인했다. 실제 사용자 기록은 교체하지 않았다. 실자료 형식 수집부터 사진 백업 왕복까지 통합 테스트를 추가했다.
