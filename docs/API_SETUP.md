# 실제 API 연결 준비

최신 키 정책: 모바일 입력 대신 개발 PC의 `.env.local`에서 키를 읽어 개인 빌드에 포함한다. 설정과 보안 경계는 [LOCAL_KEYS.md](LOCAL_KEYS.md)를 따른다.

2026-09-18 확정: 서울 전체 아파트 탐색, 출근지는 여의도 인근 지하철역(공식 역 자료에서 선택), 무료 범위. APK 빌드·설치는 기능 개발 뒤 진행한다. 2026-09-21 현재 세 서비스의 인증 응답과 서울 25구 표본 검증을 마쳤다.

## 공공데이터포털

회원가입/로그인 후 다음 세 서비스에서 활용신청한다. 개인용 아파트 탐색 및 임장 기록 앱의 개발 용도를 기재한다. 약관과 신청 조건은 사용자가 직접 확인한다.

1. [공동주택 단지 목록](https://www.data.go.kr/data/15057332/openapi.do)
2. [공동주택 기본정보](https://www.data.go.kr/data/15058453/openapi.do)
3. [아파트 매매 실거래가 상세](https://www.data.go.kr/data/15126468/openapi.do)

승인 상태를 확인하고 마이페이지의 일반 인증키 **Decoding** 값을 로컬 `.env.local`의 `NESTQUEST_PUBLIC_DATA_KEY`에 입력한다. Encoding 값을 입력하면 한 번만 디코딩한다. 채팅·Git·소스 파일에는 키를 넣지 않는다. 같은 키라도 서비스별 활용 승인이 필요하다.

공식 페이지에 포함된 Swagger를 읽어 아래 경로와 필드를 대조했다. 서비스 URL의 버전은 과거 블로그 예제를 사용하지 않는다.

- 목록: `AptListService4/getSidoAptList4`, `sidoCode=11`, 페이지별 조회. 목록 주소는 읍면동까지만 있을 수 있으므로 상세 조회 전에 정확한 건물 위치로 취급하지 않는다.
- 기본: `AptBasisInfoServiceV5/getAphusBassInfoV5` — 법정동 주소, 세대수, 동수, 난방, 사용승인일.
- 상세: `AptBasisInfoServiceV5/getAphusDtlInfoV5` — 지상/지하 주차대수 합계. 기본정보와 서로 다른 요청이다.
- 실거래: `RTMSDataSvcAptTradeDev/getRTMSDataSvcAptTradeDev`, 구별 법정동 코드 앞 5자리와 계약년월.

## 카카오 지도·주소·통근

카카오맵 사용 설정 후 기존 앱의 REST API 키를 NESTQUEST_KAKAO_REST_KEY에 등록한다. 주소 변환과 대중교통 경로 조회가 같은 키를 사용한다. 탐색 지도 SDK는 NESTQUEST_KAKAO_JAVASCRIPT_KEY와 실행 origin의 SDK 도메인 등록을 사용한다. 초기 설정의 지역 지도와 출근역 검색 자료는 앱 내 번들이다.

통근은 [카카오 대중교통 경로 API](https://developers.kakao.com/docs/ko/kakaomap/rest-api)의 출발·도착 좌표로 조회하고 가장 빠른 경로를 선택한다. 초 단위 응답을 분으로 변환하며 출근 시각 예측은 아니다. ODsay 런타임·프록시·키 주입을 제거했다. 기존 개인 키 파일은 읽거나 수정하지 않으며 남아 있는 ODsay 항목은 사용하지 않는다.

성공한 통근 결과는 IndexedDB 단지 자료에 조회일과 좌표 기반 식별자를 함께 저장하고 재실행 및 개인 백업 복원 후 재사용한다. 출발/도착 좌표가 바뀌거나 직접 갱신하거나 30일이 지나면 다시 조회한다. 30일은 앱의 갱신 기준이며 카카오가 명시한 허용 보관 기간이 아니다. [운영정책 제5조 20항](https://developers.kakao.com/terms/ko/site-policies)의 사용자 경험 목적 캐시·최신 유지 조건을 고려했다. 만료된 값은 현재 통근 필터에 사용하지 않는다. 원문 응답이나 지도 타일은 저장하지 않는다.

무료 쿼터 적용 앱의 대중교통 한도는 하루 1,000건이다. 3,400개 단지를 하루에 모두 조회할 수 없으며, 한도 도달 시 통근 호출만 중단하고 다음 이용 가능 시점에 미조회 단지부터 진행한다. 기존 유효 결과는 한도 오류가 있어도 사용한다.

## 앱에서 실행 순서

1. 초기 조건과 회사 근처 출근역을 설정한다. 출근역은 미정으로 건너뛰어도 된다.
2. `npm run keys:init`으로 로컬 키 파일을 만들고 사용자가 값을 입력한다. 개발 서버 재시작 또는 앱 재빌드 후 설정 → 실제 데이터 연결에서 등록 여부를 확인한다. 모바일 입력은 필요 없다.
3. `서울 전체 단지 가져오기`로 전체 페이지를 받은 후 저장한다. 중간 오류/누락 시 그 목록 수집은 반영하지 않는다. `탐색 범위 서울 전체로`로 조건도 변경한다.
4. 구를 선택하고 상세·위치 조회를 진행한다. 한 번에 최대 20개(단지마다 공공 API 2회와 선택적 주소 검색 최대 2회), 현재 화면의 조회 회차 내에서 이미 시도한 항목은 건너뛴다. 위치 확인이 실패해도 상세정보는 저장하고 다음 단지로 진행한다. 인증·한도·네트워크·저장 오류는 멈춘다. 미확인 위치를 재시도하려면 조회 회차를 초기화한다. 화면을 나갔다 돌아오면 회차 기록은 초기화된다.
5. 구별 최근 12개 계약월의 실거래를 조회한다. 이름+전체 지번 주소가 정확히 일치하고 거래 단지가 하나인 경우만 붙인다. 미매칭은 임의 추정하지 않는다.
6. 출근역을 선택하고 현재 조건 또는 관심/방문/최종 후보 범위에서 통근을 10개씩 조회한다. 실패/중단 후 다시 실행할 수 있다. 무료 한도에 도달하면 멈추고 다음 이용 가능 시점에 재시도한다.

표시 가격은 현재 월을 포함한 12개 계약월의 **동일 전용면적 유효 거래 중앙값**이다. 취소 거래는 제외하며 현재 매물 호가·감정평가가 아니다. 신뢰도는 거래 건수 구간에 따른 내부 표시다. 거래 정정/취소를 반영하려면 해당 구를 다시 조회한다.

## 저장과 검증의 구분

단지·실거래 자료는 사용자 기록과 함께 IndexedDB에 저장한다. 새로운 백업은 v2이고 v1은 계속 복원할 수 있다. 구버전 앱은 v2를 거부하며 단지 자료를 조용히 버리지 않는다. 사진 백업의 전체 제한은 200MiB, 단지 포함 manifest는 최대 32MiB다. 키는 백업에 포함하지 않는다. 카카오 통근 캐시는 개인 백업에 포함한다.

개발/로컬 서버에는 허용된 공공/카카오 엔드포인트만 중계하는 loopback 전용 경로가 있다. 외부 URL을 자유롭게 전달하는 프록시가 아니다. Android에서는 CapacitorHttp를 사용하므로 PC 서버가 필요 없다. 제공자가 허용하는 키 유형/호출 조건은 실제 인증 응답으로 최종 확인해야 한다.

현재 확인: 실제 인증 응답, 서울 25구 3,404개 단지 목록, 구별 기본/상세/좌표/거래 표본, 카카오 정상 경로, 실제 지도/역 선택 및 임장·사진 백업 복원. 상세 범위는 [LIVE_VALIDATION.md](LIVE_VALIDATION.md)를 따른다. Android 네트워크·카메라·파일 선택은 APK/실기기 검증 단계에 남아 있다.

## 자동 조회

첫 탐색은 지역 내 단지를 순차 조회하며 선택한 단지는 개별 조회도 지원한다. 서비스별 오류를 격리하고 중단·재시도를 제공한다. 저장한 유효 통근은 API를 호출하지 않는다. 선택한 단지에 한정하지 않고 탐색 지역 전체를 조회할 때에도 일일 한도는 적용된다.
